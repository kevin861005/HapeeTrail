# 04 — 便條樣式代號（color / style）

**What to build:** 旅人留下便條時可以指定顏色與便條紙樣式，讓便條能表達心情、在地圖上
有辨識度；撿到便條的人看到的是原作者選的樣式。代號隨便條物件與地圖 pin 一起回傳。

**後端只儲存代號、不理解其語意**——實際的顏色與樣式對照表放在裝置端，因此新增顏色或
樣式完全不需要後端 migration 或發版。代價是後端無法驗證代號是否有意義，這是刻意的取捨。

**Blocked by:** 02 — 便條與探索提示的新 wire 格式

**Status:** ready-for-agent

- [ ] 便條資料模型新增 `color` 與 `style` 兩個**獨立**的小整數欄位，既有列以預設值回填
- [ ] 兩個欄位各自獨立，**不得打包成單一數字**（打包會讓「新增第三個樣式軸」與「某軸超過 9 項」雙雙變成破壞性變更）
- [ ] 代號從 1 起算；伺服器預設值指向對照表中一個具體項目（現行黃色 ＝ 1），不得是一個「代表預設」的抽象槽
- [ ] 留下便條時兩個參數皆可省略，省略時由伺服器補預設
- [ ] 兩個代號出現在便條物件與探索提示中（地圖 pin 需要它們才能渲染成對應樣式）
- [ ] **只做型別與範圍粗檢，不驗證語意**：超出裝置端對照表範圍的代號被接受、原樣儲存、原樣回傳
- [ ] SQL seam 斷言涵蓋：預設值正確、參數可省略、超範圍代號被接受、兩個欄位互不干擾
- [ ] OpenAPI 規格與語意文件同步更新，並明載「client 遇到未知代號一律渲染預設樣式」

**注意：** 後端刻意不維護合法值清單——那等於養第二份對照表，一定會跟裝置端漂移，
會把這個設計的好處賠光。連帶接受：iOS 若有 bug 送出超範圍代號，後端照收，該便條在
所有裝置上永遠顯示預設樣式且不會有任何錯誤訊號。
