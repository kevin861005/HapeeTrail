# 05 — 私人便條（audience）

**What to build:** 旅人可以留下只給自己的便條，當作這趟旅程的紀錄。私人便條不會出現在
任何人的探索結果中、不會被任何人撿走、也不佔用未撿便條的數量上限——旅人可以長期持續
記錄旅程，而不會撞上一個原本是為了防濫用而設的限制。

私人便條正常出現在旅人自己的便條列表中，且列表要能分辨哪些是公開便條、哪些是旅遊紀錄。

**Blocked by:** 04 — 便條樣式代號（color / style）

**Status:** ready-for-agent

- [ ] 便條資料模型新增 `audience` 欄位，值為 `anyone` 與 `self` 並以 CHECK 約束；既有列回填為 `anyone`
- [ ] 此欄位使用文字型別加 CHECK，**不使用資料庫的 enum 型別**（enum 加值有交易限制、刪值幾乎不可能，而此欄位的前提就是日後會加值）
- [ ] 留下便條時參數可省略，預設為 `anyone`
- [ ] 私人便條**不出現在任何人的探索結果中**
- [ ] 他人嘗試撿取私人便條時回 `note_not_found`，且**未新增任何錯誤 token**——新增一個「這是私人便條」的 token 等於向外人確認該座標存在一張他看不到的便條
- [ ] 未撿便條的數量上限**只計算 `anyone` 便條**
- [ ] 私人便條正常出現在旅人自己的便條列表中，`audience` 值可見
- [ ] 探索用的部分索引，其條件加入 `audience`，讓熱查詢的索引更小且條件與查詢一致
- [ ] 以查詢計畫確認地理查詢仍走索引（專案守則要求地理查詢必須以 EXPLAIN 驗證）
- [ ] SQL seam 斷言涵蓋：私人便條不進他人探索結果、他人撿取回 `note_not_found`、上限不計私人便條、作者自己看得到
- [ ] OpenAPI 規格與語意文件同步更新
