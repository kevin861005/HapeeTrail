# ADR-0008：旅遊紀錄有絕對總量上限

日期：2026-07-28　狀態：已採納（T13 實作）

## 決策

`audience = 'self'` 的便條（旅遊紀錄）每個帳號上限 **5000 張**，超過拋
`private_note_limit`，附 `{"maxPrivateNotes": 5000}`。公開便條的既有上限
（`active_note_limit`，50 張未撿）不變，兩者互不影響。

與 [ADR-0006](0006-private-notes.md) 的關係：**它沒有被推翻**。0006 說的是
「旅遊紀錄不計入**未撿便條**的數量上限」，那句今天仍然成立；它對「有沒有別的上限」
是沉默的。本 ADR 補上那個沉默處——原本的實作把沉默當成了「完全不受限」。

## 理由

- 0006 把私人便條排除在未撿額度外，理由是「別讓認真記錄旅程的旅人撞上一個本來為了
  防濫用而設的限制」。那個論證支持的是**更高的上限**，不是**沒有上限**——當時的實作
  直接跳到了後者（`drop_note` 的註解甚至寫著「真出現儲存濫用再另立一個上限」，
  等於自己標記了這個缺口）。實測後果：單一帳號連建 200 張全數成功，之後仍可留滿
  50 張公開便條。
- 5000 張 ≈ 每天寫一張寫 13 年。真實使用者永遠碰不到，但單一帳號的無限累積被關掉了。

## 兩個上限為什麼不能合成一個

公開便條的額度算「**未撿的**」——被撿走就釋放，所以它是流量控制。
旅遊紀錄**永遠不會被撿走**，額度只能是絕對總量。合成一個計數會讓「公開便條滿了就不能
再記錄旅程」，那正是 ADR-0006 要避免的事。

## 已知限制（與 ADR-0003 同一立場）

這是 **advisory** 上限，不是安全邊界：

- 匿名註冊無限量，換帳號就繞過。它擋的是單一帳號的無限累積，不是定向攻擊。
- **併發下會超越，超越量 ≈ 同時在途的請求數**（計數與 insert 非原子）。實測：20 條連線
  同時搶 → 5019 張、40 條 → 5034 張；同一手法打既有的 `active_note_limit`（上限 50）
  → 65 張。兩者同級同類，實務上受連線池上限封頂。要做到精確需要 advisory lock 或
  唯一序號，對一個「防單帳號無限累積」的閘門是過度設計。
- 真出現跨帳號的儲存濫用訊號，該做的是 App Attest／裝置級識別（ADR-0003 已列為
  「未來真緩解」），而不是把這個數字調小去懲罰真實使用者。
